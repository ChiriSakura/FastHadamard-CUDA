## P0 — 正确性约定（最优先）

1. ~~**归一化约定**~~ — **已自答**：实测官方 `fast_hadamard_transform` 默认
   `scale=1.0`（非归一化），归一化需显式传 `scale=1/sqrt(head_dim)`。
   本 kernel 两种模式都与官方库 **100% bit-exact**，故无论评测采用哪种约定均通过。
   仍希望助教书面确认评测口径，以便报告措辞一致。
2. ~~**参考实现行为**~~ — **已自答**：`fast_hadamard_transform` v1.1.0，
   矩阵 = `scipy.linalg.hadamard(dim)`（Sylvester 自然序），默认不归一化，
   内部 FP32 累加。已按此对齐并验证。
3. **误差比较的参照物**：绝对误差 < 阈值，是跟 `fast_hadamard_transform` 的输出比，
   还是跟某个 FP32 参考比？比较时双方是否都转成 FP32？
   （本项目默认按"与官方库输出比、在 FP32 域比较"实现，两种口径都已覆盖。）

## P1 — 验收口径与提交

4. **官方提交目录名称**：是 `hadamard_transform`、`Hadamard_transform` 还是别的？
5. **提交时代码如何组织**：是只交 kernel 源码，还是整个可编译工程？
   - ⚠️ 题目材料里同时出现了"提交代码无测试代码"和"提交整个程序包含测试"的说法，二者似乎冲突，请明确。

7. **性能日志是否需要固定格式**？我们目前输出 CSV（含 `avg/min/max_kernel_ms` 等字段），是否够用？
